## 1. 目的与范围

本规范定义 AI Agent 记忆系统的设计、实现、测试与运维准则。

核心观点：**记忆系统不是存储问题，而是信息生命周期管理问题。** 应把记忆当作有生命周期、有来源、有质量管控的数据资产来管理，而不是一个只增不减的存储桶。

本规范是记忆系统文档体系的基础件。**文档体系的登记以《学习伴侣系统开发规范》§2 为唯一权威源**（单一权威源原则——多份登记表必然漂移，本项目已有先例：压力规范入体系时本表漏同步，直至 v1.5 才补上）；本文不再维护登记副本。

本产品的部署与合规边界以《部署与数据边界规范》为准，本文第 8 / 9 章的相关条款受其约束。

## 2. 术语定义

| 术语 | 定义 |
| --- | --- |
| 工作记忆 | 当前会话上下文内的临时信息，随会话结束消亡 |
| 情景记忆 | 具体交互事件的记录（"某次对话中发生了什么"） |
| 语义记忆 | 从交互中提炼的稳定事实（"用户偏好深色主题"） |
| 程序性记忆 | 技能与操作流程（"处理退款要先查订单状态"） |
| 写入 | 将信息固化为记忆的过程 |
| 检索 | 依据当前上下文召回相关记忆的过程 |
| 裁决 | 新旧记忆冲突时决定保留、取代或合并的规则 |
| 遗忘 | 主动衰减、归档或删除记忆的机制 |

## 3. 总体设计原则（总纲）

1. **分层设计**：不同类型的记忆分开建模、分开存储，不允许一个池子混装。
2. **写入有门槛**：错误记忆比没有记忆更糟。
3. **读取有预算**：每条进入 prompt 的记忆都必须"值回它的 token 成本"。
4. **全生命周期管控**：记忆可更新、可裁决、可遗忘、可审计。
5. **从简单开始**：先跑通朴素方案，凭失败案例驱动演进，不做超前架构。

## 4. 记忆模型规范

### 4.1 分层结构（必须）

记忆**必须**至少划分为以下四层，各层的留存时长、写入门槛、检索方式独立定义：

| 层 | 留存 | 写入门槛 | 典型检索方式 |
| --- | --- | --- | --- |
| 工作记忆 | 会话内 | 无（随上下文） | 直接在上下文中 |
| 情景记忆 | 中长期 | 中 | 向量 + 时间过滤 |
| 语义记忆 | 长期 | 高 | 混合检索 + 结构化过滤 |
| 程序性记忆 | 长期 | 高（需验证） | 显式调用 / 工具化 |

**工作记忆边界（必须）**：工作记忆是上下文窗口的一部分，**不是**记忆记录——它**不得**进入持久层与证据日志，不参与审计与重放；会话结束即丢弃。需要保留的**必须**经第 5 章写入门槛转为情景记忆。

### 4.2 记忆条目 Schema（必须）

每条记忆**必须**携带以下元数据字段：

```text
memory_id        唯一标识（全局唯一，跨导出 / 导入稳定）
type             记忆层级（episodic / semantic / procedural）
content          记忆内容（结构化字段 + 非结构化文本）
source           来源（哪次交互 / 谁陈述 / 哪个外部输入）
source_trust     来源可信级别（user_direct / agent_inferred / external）
audience         受众域（本条记忆可被哪些消费方检索：child / parent / system）
created_at       创建时间（事件时间，见 4.4）
last_validated   最近被确认有效的时间（派生缓存）
valid_until      有效期（派生缓存，可为空）
confidence       置信度
status           状态（active / superseded / archived / deleted）
supersedes       本条取代了哪些记忆（版本链）
```

没有 provenance（来源与时间）的记忆无法参与冲突裁决，也无法审计，**不得**入库。

`source_trust` 分级**可以**按产品域扩展。例如儿童产品中，`user_direct` 应进一步细分为**已确认 / 未确认**——儿童口述天然不可靠，未确认的直述参与决策时必须降权（参见学习伴侣记忆反模式 AP-LC-09）。

**派生时间字段（必须）**：`valid_until`、`last_validated` **应当**声明为**派生缓存**——权威值由证据与时间重算得出，**不得**作为可旁路修改的独立状态（与《掌握度记忆生命周期规范》2.2 的可重放不变量一致）。

**标识稳定性（必须）**：`memory_id` **必须**全局唯一且跨导出 / 导入稳定——导入同一档案的导出文件时，同一记忆**必须**按同一 id 识别，**不得**复制为新条目（与 7.4 复活语义、部署规范 6.2 幂等并集一致）。

**受众域（必须）**：`audience` **必须**在写入时确定，**不得**由检索方临时推断；家长 / 教师侧标注类记忆**必须**标记为 `parent`，且**不得**进入儿童端检索路径（见 8.5）。

### 4.3 结构化与非结构化并存（应当）

用户画像类事实（偏好、属性）**应当**以结构化字段存储；事件叙述**可以**保留非结构化文本。检索时结构化字段用于精确过滤，文本用于语义匹配。

### 4.4 时间语义（必须）

- 所有时间戳**必须**时区明确（存储 UTC 或带偏移量），**不得**依赖本地时区的隐式解释；
- TTL、衰减、有效期、统计窗口类计算**必须**基于单调时间语义与可信时间源；设备时钟回拨**不得**倒转衰减、**不得**重置时间窗（详见《部署与数据边界规范》2.4）；
- 时间字段**必须**区分**事件时间**（事实发生的时刻，不可变）与**记录时间**（系统写入的时刻）；离线补处理的写入**必须**以事件时间参与计算（同上 2.5）。

## 5. 写入规范

### 5.1 写入门槛（必须）

**必须**定义明确的写入策略，至少包含以下之一：

- 显式触发：用户明确要求记住（"记住这个"）；
- 重要性评分：达到阈值才写入；
- 频次信号：同类信息多次出现才固化。

禁止"对话全文无差别入库"。

### 5.2 写入质量（必须）

写入前**必须**执行：

1. **去重**：与既有记忆语义重复的不重复写入；
2. **原子化**：一条记忆表达一个事实，不把多个事实揉进一条；
3. **脱敏**：敏感信息按第 8 节处理后再入库。

### 5.3 异步写入（应当）

记忆写入**应当**在主响应路径之外异步完成，写入失败不得阻塞或破坏主对话流程。

### 5.4 写入失败与可见性（必须）

写入失败**不得**静默丢弃：

- **显式触发类**（5.1 的"记住这个"）失败**必须**可观测——要么重试至成功，要么明确告知用户"没有记住"；**不得**让用户误以为已记住（静默欺骗属信任损害，与编造记忆同类）；
- 自动 / 推断类写入失败**可以**丢弃，但**必须**留痕（可诊断、可统计失败率）；
- 重试**必须**有上限与退避；超限后的处置（转入待办队列或丢弃）**必须**事先定义并留痕。

## 6. 读取 / 检索规范

### 6.1 混合检索（应当）

**应当**采用混合检索：向量召回（语义）+ 关键词匹配（精确）+ 结构化过滤（元数据），召回后做精排。

### 6.2 精度优先（必须）

检索精度（precision）优先于召回率（recall）。**必须**对进入 prompt 的记忆做数量或相关性截断；无关记忆会稀释模型注意力，其危害大于漏掉一条相关记忆。

### 6.3 排序信号（应当）

排序**应当**综合考虑：相关性、时近性（recency）、重要性、置信度。过时信息即使高度相关也要降权。

### 6.4 延迟预算（必须）

**必须**为检索路径设定延迟预算（建议 ≤ 500ms 量级），超预算的检索降级为跳过或仅用缓存，不得拖垮 agent 主循环响应。

### 6.5 检索准入过滤（必须）

检索结果**必须**先经准入过滤，再做排序与截断：

1. **状态过滤**：`status` 为 `superseded` / `archived` / `deleted` 的记忆默认**不得**进入检索结果；需要历史回溯时（审计、报告追溯）**必须**显式声明，**不得**作为默认行为；
2. **受众过滤**：按消费方过滤——仅检索 `audience` 包含该消费方的记忆；家长 / 教师侧记忆**不得**进入儿童端检索路径（8.5）；
3. **敏感度过滤**：加密受限记忆（8.2）默认不参与常规检索，仅可经显式授权路径访问；
4. 过滤**必须**在本地完成；部署规范 7.2 的禁发清单以本过滤结果为基准——**"可进入儿童端 prompt 的记忆 = 可发云端推理的记忆"**。

## 7. 生命周期管理规范

### 7.1 更新优先于追加（必须）

新信息与既有记忆矛盾时，**必须**走"取代 / 版本化"语义（通过 `supersedes` 字段建立版本链），不得盲目 append 留下两条互相矛盾的记忆。

**合并语义（必须）**：多条**互补而不矛盾**的记忆（同一主题的不同侧面）**可以**合并为一条；合并结果的 provenance **必须**可追溯至全部来源（来源引用与时间信息不得在合并中丢失），且**必须**产生新版本而非抹除原条目。

### 7.2 冲突裁决优先级（必须）

裁决规则**必须**事先明文定义，默认优先级如下（高 → 低）：

1. 来源可信级别（`user_direct` > `agent_inferred` > `external`；产品域扩展见 4.2）；
2. **同一可信级别内**，显式程度（用户显式声明 > 系统推断）；
3. 时间更近；
4. 置信度更高。

**裁决留痕（必须）**：每次裁决**必须**记录胜出条目、依据的优先级条目与被取代条目（版本链），供追溯与报告生成（8.4）。

### 7.3 时效性（应当）

事实类记忆（地址、状态、进度）**应当**携带 `valid_until` 或定期重验证；被取代的记忆标记 `superseded` 而非直接删除，保留审计能力。

`valid_until` / `last_validated` **应当**为派生缓存（4.2）：采用可重放架构的产品**必须**使其可由证据与时间重算，**不得**作为唯一权威来源（否则"存储值 ≠ 重算值"的分裂将破坏重放一致性判定）。

### 7.4 遗忘机制（必须）

**必须**实现以下遗忘手段中的至少两种：

- TTL 到期自动归档；
- 重要性衰减（长期未被检索命中的记忆降权、归档）；
- 容量上限触发淘汰；
- 用户主动删除。

归档条目被再次触发（如用户显式重申）时，**必须**复活为同一条记忆的重新激活（刷新时间与状态），**不得**新建重复条目；复活历史可追溯。

### 7.5 容量治理（必须）

长期记忆**必须**设定容量预算（条数或体积）与超限淘汰顺序；本地部署产品（存储受限）尤须如此：

- 淘汰**必须**按 7.4 的遗忘手段执行，**不得**静默丢弃记忆；用户显式触发的记忆（5.1）淘汰优先级最低；
- 容量占用、淘汰次数与淘汰对象**应当**可观测（9.3）。

## 8. 安全与隐私规范

### 8.1 用户控制（必须）

**必须**为用户提供记忆的查看、编辑、删除入口；"删除"**必须**是硬删除或不可恢复匿名化，且同步清理派生数据（摘要、向量索引、由该记忆派生的结论字段、家长端副本）。

**删除优先于不可变（必须）**：法务 / 用户删除权优先于报表流水不可变、审计留存等工程便利——已生成的历史报告中包含被删除数据时，**必须**按删除要求处置（去标识化或删除），**不得**以"历史记录不可变"为由保留（与《掌握度记忆生命周期规范》2.3 的报表不可变条款冲突时，以本条为准）。

### 8.2 数据最小化（必须）

只记忆达成任务所需的最少信息。身份敏感信息（证件号、住址、健康信息等）入库**必须**加密并限制检索范围；未成年人相关产品需额外遵守未成年人保护法规。

**密钥管理（必须）**：加密**必须**配套密钥生命周期管理——生成、轮换、与设备绑定、丢失处置；密钥**不得**与密文存放于可被一并读取的位置；密钥丢失时的数据处置策略（不可恢复 / 可恢复路径）**必须**事先定义且对用户可告知。

### 8.3 防记忆投毒（必须）

不可信来源（网页内容、第三方消息、工具返回）**不得**直接固化为长期记忆；外部信息入库必须：

1. 标记 `source_trust = external`；
2. 与用户亲述记忆隔离存储；
3. 参与决策时降权或需用户确认。

防止一次 prompt injection 让 agent 永久"记住"恶意指令。

仅防入口不足以防投毒：防线被绕过、或污染在事后才被发现时，**必须**有清除路径（见 8.6）。

### 8.4 审计日志（应当）

记忆的写入、更新、裁决、删除操作**应当**留有审计日志，可回答"agent 为什么这么做的"（当时检索到了哪些记忆）。

### 8.5 受众隔离（必须）

记忆**必须**按受众域隔离存储与检索：

1. 受众域**必须**在写入时确定（4.2 `audience`），**不得**由检索方临时推断；
2. 儿童端检索路径**不得**可见家长 / 教师侧记忆——隔离**必须**在检索层强制（6.5），**不得**依赖话术层过滤或事后清洗；
3. 家长 / 教师侧记忆**可以**经显式设计的策略层间接影响体验（如难度调整），但**不得**将内容本身注入任何面向儿童的输出；
4. 跨受众域的读取**必须**留审计（8.4）。

### 8.6 污染处置（必须）

发现已被固化的污染 / 错误记忆时，**必须**可执行处置流程：

1. 按来源标记与证据链**定位**受影响的记忆范围（8.3 / 8.4）；
2. **隔离**或删除污染条目，并回滚由它派生的结论（依赖可重放不变量，见《掌握度记忆生命周期规范》2.2）；
3. 追溯受其影响的输出（哪些回复 / 报告引用了它，8.4），必要时更正；
4. 处置动作**必须**留审计。

## 9. 工程实现规范

### 9.1 存储选型（应当）

- 热数据（近期情景记忆）：向量库 / 内存缓存；
- 冷数据（历史归档）：对象存储 / 列式存储；
- 结构化画像：关系型数据库；
- 学习伴侣场景：全部层级（含向量检索）落地**设备本地存储**（见《部署与数据边界规范》2.1）。

选型遵循"够用即可"，禁止为想象中的规模引入重型组件（参见第 11 节）。

### 9.2 同步与一致性（应当）

记忆更新与主流程解耦（后台任务）。本产品部署形态为**设备本地唯一权威源**（见《部署与数据边界规范》2.1），无云同步；跨设备数据流转仅通过**导出 / 导入**完成，合并语义见该规范第 6 章。

### 9.3 可观测性（应当）

暴露核心指标：写入速率、检索延迟分布、检索命中率、记忆库规模增长曲线、冲突裁决次数。

## 10. 测试与评估规范

### 10.1 记忆操作回归测试（必须）

写入、去重、合并、冲突裁决、遗忘**必须**有自动化回归测试，尤其是冲突裁决的优先级规则。

### 10.2 端到端评估（必须）

过程指标（检索 precision / recall）只是参考，**必须**以**下游任务是否因记忆而改善**作为验收标准：同一任务集上，带记忆 vs 不带记忆做 A/B 对比。

### 10.3 毒化与对抗测试（应当）

**应当**包含记忆投毒测试用例：注入恶意"记忆"后，验证其不会影响 agent 行为。

## 11. 演进原则（YAGNI）

- **必须**从最简可行方案起步：原始对话存档 + 滚动摘要 + 结构化用户画像，即可覆盖多数场景；
- 图谱记忆、分层压缩等高级能力**可以**引入，但仅当有具体失败案例证明简单方案不足时；
- 每次架构升级需附带失败案例分析与评估数据（依据 10.2）。

## 12. 反模式（评审时对照）

| 反模式 | 违反条款 |
| --- | --- |
| 对话全文无差别入库 | 5.1 |
| 只增不删、无任何遗忘机制 | 7.4 |
| 新旧矛盾记忆并存、无裁决 | 7.1 / 7.2 |
| 记忆无来源、无时间戳 | 4.2 |
| 记忆无受众域，家长侧记忆可被儿童端检索 | 4.2 / 8.5 |
| 检索不过滤 superseded / archived / deleted | 6.5 |
| 检索结果全量塞进 prompt | 6.2 |
| 外部网页内容直接固化为长期记忆 | 8.3 |
| 发现污染记忆后无隔离 / 回滚路径 | 8.6 |
| 显式触发的写入失败被静默丢弃 | 5.4 |
| 无用户删除入口，或删除后向量索引残留 | 8.1 |
| 以"历史记录不可变"为由拒绝删除 | 8.1 |
| 派生时间字段（valid_until 等）被当作独立权威状态 | 4.2 / 7.3 |
| 依赖本地时区隐式解释时间戳 | 4.4 |
| 加密无密钥管理配套 | 8.2 |
| 只测检索指标、不测下游任务效果 | 10.2 |
| 一上来就上图数据库 / 知识图谱 | 11 |

> 本表为**通用层**；学习伴侣（教育场景）的领域细化见《学习伴侣》反模式手册（AP-LC-01 ~ 28，v2.0 合并版），两层层级配合使用——通用条目在儿童产品中的具体表现与更严要求以 AP-LC 为准。

## 13. 合规检查清单

上线评审时逐项勾选：

- [ ] 记忆已按四层分类，各层写入/留存/检索策略已定义；工作记忆不入持久层（4.1）
- [ ] 记忆条目含完整元数据 schema：source_trust / audience 分级已按产品域定义（4.2）
- [ ] memory_id 跨导出 / 导入稳定，导入不产生重复条目（4.2）
- [ ] 时间戳时区明确，分事件时间与记录时间（4.4）
- [ ] 有明确写入门槛，无全文入库（5.1）
- [ ] 写入前执行去重、原子化、脱敏（5.2）
- [ ] 写入异步化，不阻塞主流程（5.3）
- [ ] 显式触发类写入失败可观测，无静默丢弃（5.4）
- [ ] 混合检索 + 精排，有截断策略（6.1 / 6.2）
- [ ] 检索经准入过滤（状态 / 受众 / 敏感度），过滤在本地完成（6.5）
- [ ] 检索延迟预算已定义并监控（6.4）
- [ ] 记忆矛盾走取代/版本化（supersedes），无盲目 append（7.1）
- [ ] 互补记忆合并保留全部来源可追溯（7.1）
- [ ] 冲突裁决规则已明文定义并有测试；裁决结果留痕（7.2 / 10.1）
- [ ] 事实类记忆带有效期或定期重验证；派生时间字段可重算（7.3）
- [ ] 至少两种遗忘机制已实现（7.4）
- [ ] 容量预算与超限淘汰策略已定义，不静默丢失显式记忆（7.5）
- [ ] 用户可查看/编辑/删除记忆，删除含派生数据清理（8.1）
- [ ] 删除优先于报表不可变，历史报告按删除要求处置（8.1）
- [ ] 敏感信息加密存储并限制检索范围，配套密钥生命周期管理（8.2）
- [ ] 不可信来源记忆已隔离并降权（8.3）
- [ ] 受众域隔离在检索层强制，儿童端不可见家长侧记忆（8.5）
- [ ] 污染处置流程（定位 / 隔离 / 回滚 / 更正）已定义（8.6）
- [ ] 有审计日志（8.4）
- [ ] 记忆操作有自动化回归测试（10.1）
- [ ] 带记忆 vs 不带记忆的 A/B 评估已执行（10.2）
- [ ] 首版未引入超出需要的高级组件（11）
