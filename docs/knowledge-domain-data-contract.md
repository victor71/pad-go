## 1. 目的与范围

记忆系统的核心签名是 `state = f(证据日志, 时间, 元数据版本)`（生命周期规范 2.2），图传播、难度判定、兴趣预测、教材迁移全部依赖知识点域的数据。本契约定义这个域的**数据形态与不变量**，使记忆系统的设计、实现与重放不依赖数据的具体生产方式。

三份子契约统一于一套版本机制：

1. 知识点注册表（kp_code 编码与生命周期）；
2. 前置关系图（边类型与消费边界）；
3. 题目-知识点关联（含难度标定）。

**本契约不是被否决的"题目-知识点关联方案"**：方案回答"十万级题目如何打标"，契约只回答"打好的标长什么样、带什么不变量、如何版本化"。数据初期可以粗糙（甚至部分为空），契约先行使记忆系统的设计、测试（M-12 / M-19、fixture 元数据版本对）可以先行。

## 2. 术语

| 术语 | 定义 |
| --- | --- |
| kp_code | 知识点的全局唯一、跨教材版本不变的标识 |
| 知识点注册表 | 全部知识点的权威清单（身份、名称、状态、继任关系） |
| 强前置边（requires） | 未掌握 A 则 B 不可学的依赖 |
| 元数据版本 | 注册表 + 前置图 + 关联集 + 难度表的整体不可变快照 |
| 教材映射 | 教材版本 → 章节路径 → kp_code 的映射，与 kp 身份正交 |

## 3. 知识点注册表（kp_code 编码规范）

### 3.1 编码规则（必须）

- kp_code **必须**为不透明字符串（如 `kp` 前缀 + 不重复的序列 / 随机段）；**不得**内嵌教材、年级、章节、学科等语义——这些是会变化的属性，内嵌语义的 code 无法跨版本稳定（AP-LC-14 的前提）；
- **全局唯一，跨教材版本不变**：同一概念在所有教材版本中共用同一 code；
- **退役 code 永不复用**：code 一旦注销，**不得**再分配给任何其他概念（防悬空引用被劫持；同概念回归走重新激活，见 3.3）。

### 3.2 身份不变性（必须）

| 可变（随元数据版本更新） | 不可变 |
| --- | --- |
| 名称、描述、认知层级建议、典型难度带 | kp_code 本身；既有证据对 code 的引用 |

重命名、描述修订、难度重标**不得**产生新 code。

### 3.3 注册表生命周期（必须）

知识点状态：`active ⇄ dormant`（休眠/重新激活，code 不变）与 `active → split / merged / retired`，后三者必须携带 `superseded_by`（继任 code 列表）：

- **split**（一拆多）：新 code 创建，旧 code 标注继任列表；学情迁移按继任链进行（M-19 的 1:N 变体）；
- **merged**（多合一）：保留或新建一个 code，其余标注继任（N:1 变体）；
- **retired**（概念退役）：墓碑状态，引用保留（报表可溯）；同概念回归时**可以**重新激活（code 不变），但**不得**把退役 code 分配给其他概念。

### 3.4 粒度规则（应当）

- 一个 kp **应当**能被单道典型题在单一认知步骤内诊断；总是需要多题组合才能测的，**应当**拆分；
- 复合能力不拆分时，**必须**在关联层多绑定（第 5 章）并接受归因噪声（AP-LC-03）；
- 粒度调整（拆分 / 合并）是重大变更：走 3.3 生命周期，触发全量学情重算。

## 4. 前置关系图 schema

### 4.1 边类型与消费边界（必须）

| 类型 | 语义 | 图传播 | 难度门禁 | 推荐邻接 |
| --- | --- | --- | --- | --- |
| `requires`（强前置） | 未掌握 A 则 B 不可学 | ✔（传递） | ✔ | ✔ |
| `supports`（弱支持） | 有 A 更易学 B，无 A 亦可 | ✘ | ✘ | ✔ |
| `relates_to`（关联） | 主题 / 因果 / 应用关联 | ✘ | ✘ | ✔ |

**图传播与难度门禁只走已确认的强前置边**（生命周期 7.1、伴学 6.2）；`supports` / `relates_to` 只服务推荐与兴趣预测（伴学 6.3、AP-LC-24）。这张表就是本契约对下游全部消费方的边界承诺。

### 4.2 边属性（必须）

```text
edge = { from_kp, to_kp, type, source, status, note }
source ∈ { 教研确认, 规则导出, 模型推断 }
status ∈ { active, retired }
```

- `source` 为**规则导出 / 模型推断**的边**不得**参与图传播与难度门禁，只可用于推荐邻接（降权）——推断性结构不得成为硬门禁，这是"推断不落盘"原则在元数据侧的映像；
- 推断边经教研确认后改 `source = 教研确认`，自下一元数据版本起获传播资格。

### 4.3 图不变量（必须）

1. `requires` 边构成 **DAG**（无环、无自环）——传播终止性与前置链可解释性（"缺哪些前置"）的前提；
2. 边端点必须是注册表中 active / dormant / 墓碑状态的 kp（无孤儿边）；
3. 同一对 kp 可并存不同类型的边；同类型同方向不允许重复。

### 4.4 消费矩阵

| 消费方 | 读取 | 约束 |
| --- | --- | --- |
| 生命周期 · 图传播（7.1） | active `requires` 的传递闭包 | 只读；推断边禁入 |
| 难度判定 / 可及性解释（伴学 6.2） | `requires` 闭包 + 难度带 | 输出必须可解释 |
| 兴趣预测 / 探索义务（伴学 6.3–6.5） | `supports` / `relates_to` 邻接 | 只做推荐，不做门禁 |
| 诊断性判定（生命周期 5.2） | 难度表 + 关联置信度 @ 指定版本 | 版本是重放参数 |

## 5. 题目-知识点关联契约

### 5.1 条目 schema（必须）

```text
binding = { question_id, kp_code, role, confidence, source }
role      ∈ { primary, secondary }   // 复合题主辅考点（AP-LC-03）
confidence ∈ [0, 1]
source    ∈ { 题库导入, 教研标注, 规则匹配, 模型推断 }
```

### 5.2 生效规则（必须）

- 一道题**必须**至少一条 binding 才可产生学情证据；**无绑定的题目只能作为参与型内容，不产生任何掌握度证据**；
- binding 按 confidence 加权进入掌握度更新（生命周期 7.2、AP-LC-03）；低于配置阈值的 binding **不得**单独支撑升级行为，只可参与降权证据；
- 关联修正 = 新元数据版本 + 变更日志；旧证据在新版本下重放重算（生命周期 2.2），已发报告不改写（2.3）。

### 5.3 难度标定表（应当）

每个元数据快照**应当**携带题目难度标定（至少序数带）——诊断性判定的"难度匹配"依赖它（生命周期 5.2）；标定方法属方案层。

## 6. 元数据版本机制

### 6.1 快照（必须）

`元数据版本` = {注册表状态， 前置图边集， 关联集， 难度表} 的**整体不可变快照**，单调递增编号；快照一经发布**不得**修改，任何修正 = 新快照。

### 6.2 变更日志（必须）

每个新版本**必须**携带变更日志（改了什么、为什么），供重算差异解释（M-12 的"因为题目标注修正，重新评估了这批知识点"话术的数据来源）。

### 6.3 消费规则（必须）

- 生命周期重算**必须**显式指定元数据版本（可测性需求 #2：版本可固定 / 切换）；
- **证据不内嵌元数据版本**——版本是重放参数，不是证据属性（防双重编码）；
- 记忆系统对元数据**只读**；元数据的生产与维护属上游治理（第 8 章）。

## 7. 教材版本映射

### 7.1 映射 schema（必须）

```text
edition = { 教材版本ID（出版社 + 学段 + 年级 + 册次）, 章节树 }
章节节点 → kp_code 集合（该章节覆盖的知识点）
```

章节路径**只存在于映射中**，不得进入 kp 身份（3.1）。

### 7.2 改版迁移规则（必须）

- 教材改版**不得**为未变概念新建 kp_code（AP-KP-01）：改版 = 新 edition + 新映射，概念不变则 code 不变，学情**依构造**保留（M-19 的 1:1 主路径）；
- split / merged 知识点的学情迁移按 `superseded_by` 链进行（M-19 的 1:N / N:1 变体）；
- 孩子升学 / 换教材 = 学习范围（scope）重解析，**不是**学情重置——这是生命周期规范 3.3 搁置语义的输入源。

## 8. 治理

- 注册表为**单一权威源**；code 分配、split / merge / retire、边确认、休眠/激活均为治理事件，**必须**留审计（谁、何时、何因——与记忆规范 8.4 同构）；
- **应当**指定教研权威角色，负责推断边确认与粒度调整评审（角色可以后补，流程先行）；
- 快照发布前**必须**通过质量门禁：4.3 图不变量校验（DAG / 孤儿边 / 重复边）+ 第 5 章绑定校验。
