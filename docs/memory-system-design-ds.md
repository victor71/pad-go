## 1. 本文的组织方式

v0.1 以**组件**为单位组织（咽喉点 + 组件清单）。本文改以**运行时契约**为单位：先定义系统对外承诺的六份契约（前置条件、后置条件、不变量、违反时的失败用例），再让组件成为契约的实现者。

选择这个组织方式的理由：规范体系本身是**契约式**写的（必须/应当/不得 + 用例追溯），而**可评审性**来自"每条承诺能否被一条用例否证"。组件图容易让人讨论边界画得好不好看，契约表强制讨论"这个承诺是否成立、被什么用例否证"。

## 2. 第一原理：四个不可违背的问题

技术选型之前，系统必须先能回答四个问题。每一个都对应规范体系里最硬的一批条款：

| 问题 | 含义 | 硬约束来源 |
| --- | --- | --- |
| **Q1 什么是真的？** | 学情结论必须可追溯到证据，不得有第二个真相来源 | 生命周期 2.2 可重放、记忆 8.4 审计 |
| **Q2 谁可以看？** | 同一份记忆，儿童端 / 家长端 / 策略层可见性不同 | 记忆 6.5 / 8.5 受众隔离、部署 7.2 禁发清单 |
| **Q3 什么东西离开了设备？** | 每一次外发可枚举、可审计、可拒绝 | 部署 2.2 白名单、7.2 最小必要、7.4 调用审计 |
| **Q4 忘记了会不会被记住？** | 删除是不可逆的终态，不是软标记 | 记忆 8.1 删除优先于不可变、S-06 |

**设计的第一原则由此得出：凡答案不在设备本地的，都有一个收口点；凡收口点，都有审计。** 不存在"反正没人查"的旁路。

## 3. 六份运行时契约

契约违反时的对应用例即验收标准（用例编号见用例集 v1.6）。

### K1 · 证据契约（Evidence Contract）

- **前置**：儿童档案上下文 + 原始交互（作答 / 对话 / 探索行为）+ 当前元数据版本
- **后置**：证据条目持久化并纳入重放序列；**或者**明确拒绝 / 降级（且失败可见）
- **不变量**：
  1. 无直接证据不入库；推断**不得**落盘
  2. 跳过 / 未作答 → 行为信号，**不得**成为失败或正确证据
  3. 归因标记（受上游阻塞 / 受状态受限）在持久化**之前**写入，非事后补救
  4. `evidence_id` 幂等；事件时间不可变，与记录时间分列
  5. 显式触发类写入失败**可观测**（重试至成功或告知未记住）；自动类留痕
  6. 写入不得阻塞主对话（异步，但有界）
- **否证用例**：W-06（静默丢失）、M-30（跳过语义）、M-28（状态受限归因）、X-03（推断落盘）

### K2 · 投影契约（Projection Contract）

- **前置**：证据日志 + 时钟 + 元数据版本
- **后置**：任一 (儿童, kp) 的投影 = `f(证据, 时间, 元数据版本)` 的唯一确定结果
- **不变量**：
  1. **确定性**：同三元组输入必得同输出（重放可自比对）
  2. 投影**可丢弃**：删除投影不损失任何信息
  3. 版本标记 `(meta_version, evidence_seq, clock_anchor)` 使不一致**可检测**
  4. 一切调度参数（重验间隔、下次重验时间、压力档位）为**派生值**，不作为权威存储
  5. 降级判定只对 {部分掌握, 达标} 生效；未达标水平的失败不构成降级事件
- **否证用例**：X-01（重放自比对）、X-07（投影完备性）、M-29（探索期不降级）、M-12（版本切换）

### K3 · 读取契约（Recall Contract）

- **前置**：消费方身份（儿童端 / 家长端 / 策略层 / 报告）
- **后置**：结果集 + **审计记录**（命中项与被过滤项及原因码）
- **不变量**：
  1. **准入过滤先行**：状态 → 受众 → 敏感度，过滤在排序与截断之前
  2. 受众过滤在**检索层**强制，不依赖渲染层清洗
  3. 截断必须有；精度优先于召回
  4. 延迟预算内返回，超时降级而非阻塞
  5. 四端读**同源全景**，不允许私有副本
  6. 消费方**不得**绕过本契约直读记忆库
- **否证用例**：S-04（家长标注隔离）、R-05（状态过滤）、C-05（未命中不得编造）、R-03（超预算降级）

### K4 · 外发契约（Egress Contract）

- **前置**：已组装的推理请求 + 目的声明（或：内容包拉取 / 家长直连请求）
- **后置**：审计记录；或拒绝
- **不变量**：
  1. **四通道白名单**：内容下行、推理调用、C5 遥测、家长直连；其余零外发
  2. **禁发清单恒空**：家长标注 / 加密记忆 / 审计日志 / 他档数据 / 全量档案
  3. 最小必要：仅对话历史 + 截断后记忆 + 系统指令
  4. 每调用审计（时间 / 目的 / 条目数 / 来源 kp）
  5. 离线时入持久队列，补处理携带**事件时间**
- **否证用例**：BD-07（白名单）、BD-10（载荷）、BD-09（未配对直连拒绝）、N-06（离线补处理）

### K5 · 治理契约（Governance Contract）

- **前置**：家长验证 + 对应同意项（C1–C5）
- **后置**：操作完成 + 审计留痕；或拒绝
- **不变量**：
  1. 同意项**不常驻**：导出 / 导入 / 删除每次单独验证
  2. 撤回 C1 = 停用（不删）；删除仅走 C4
  3. 导出认证加密、零明文；导入验签失败**整体拒绝**
  4. 导入 = 幂等并集 + 全量重放；信任**不升级**
  5. **删除优先于不可变**：级联至投影、索引、摘要、家长 App 副本、历史报告去标识
  6. 密钥与密文分离存放；丢失处置事先定义
- **否证用例**：BD-01 / BD-02 / BD-03 / BD-05、S-06、BD-11、BD-06（撤回语义）

### K6 · 内容契约（Content Contract）

- **前置**：签名内容包（元数据快照：注册表 / 图 / 关联 / 难度）
- **后置**：验签后只读挂载 + 版本注册；切换触发重算
- **不变量**：
  1. 快照**不可变**、单调递增、强制变更日志
  2. **推断来源的边不得参与图传播与难度门禁**（只可推荐邻接）
  3. `requires` 构 DAG；无孤儿边
  4. kp_code 不透明、跨教材版本不变、退役不复用
  5. 无绑定题目不产生学情证据
- **否证用例**：S-05（内容投毒）、M-12（版本切换重算）、M-19 / M-27（迁移与 code 生命周期）

## 4. 存储分层：不可变内核 / 可重建外环 / 可再获取

不按"表"分类，按**丢失后的后果**分类——因为它直接决定备份、删除、重建三件事怎么做：

| 层 | 内容 | 丢失后果 | 可否重建 |
| --- | --- | --- | --- |
| **内核（不可重建）** | 证据日志、审计日志、同意记录、记忆条目本体（含 supersedes 链）、密钥 | **不可恢复**：真相丢失 | ✗ |
| **可重建外环** | 掌握度投影、全景、向量索引、摘要、检索倒排 | 无信息损失 | ✓（由内核重放 / 重算） |
| **可再获取** | 内容包及其衍生索引 | 无信息损失 | ✓（重新下载 + 验签） |

由此推出的三条规则：

1. **备份只备份内核**（外环重建成本低于传输成本）；
2. **删除先删内核、再废外环**（顺序反了会出现"索引残留指向已删记忆"）；
3. **任何"不确定就重算"的操作只允许发生在外环**——内核永不被重写（审计与同意记录尤其不可变，唯一例外是删除权的终态处置）。

## 5. 信任域与通行证

在物理档案隔离（每儿童独立加密库）之上，叠加一层**受众域**规则（K3 的语义基础）：

| 域 | 内容 | 可见方 |
| --- | --- | --- |
| **A 儿童域** | 儿童对话、作答、儿童端呈现素材 | 儿童端、策略层（读） |
| **B 成人域** | 家长标注、报告、控制项 | 家长端、策略层（读） |
| **C 系统域** | 证据元数据、审计、探针编排 | 策略层、治理组件 |

规则：

1. 域内自由流动；**跨域读取需通行证**（显式声明用途 + 落审计）；
2. **A 不可见 B 的内容**——单向硬隔离；A 只能感知 B 的**策略效果**（如难度被调整），不能感知其内容；
3. C 可读 A / B 用于策略与审计，但受 K4 禁发清单约束（读得到 ≠ 发得出）；
4. 通行证不是权限位，是**每次调用的显式参数**——避免"一次授权终身可读"的漂移。

## 6. 执行模型与并发

v0.1 未展开的部分，此处补上：

- **单写者**：证据日志由单一写者进程持有，序号单调递增 → 证据天然全序，重放无需处理并发歧义。这是 K2 确定性的结构性前提（而非靠排序算法补救）。
- **任务优先级**：证据写入 > 投影增量重放 > 探针执行（受预算/aging 约束）> 索引维护 > 全量重算 > 索引重建。低优先级任务**可被抢占且可延迟到闲置窗口**。
- **重算窗口**：全量重算（元数据版本切换、导入后）安排在充电 + 闲置；期间旧投影继续服务，靠版本标记检测不一致并对读取方回退到增量补放。
- **离线队列**：智能级任务持久化排队（对话生成、语义提取、前兆信号中的对话分析）；联网后按事件时间补处理。
- **读取并发**：读取方无锁读投影（不可变快照 + 版本标记）；读到不一致版本时等待或按标记回退，**不**加写锁阻塞儿童作答。
- **崩溃恢复**：证据日志 WAL + `evidence_id` 幂等 → 撕裂重放一致（X-06）。

## 7. 失效模式分析

| 失效 | 系统行为 | 用户可见 | 数据后果 |
| --- | --- | --- | --- |
| 云端 LLM 不可达 | 智能级暂停、对话降级；作答证据照常 | 对话不可用，学习不中断 | 无 |
| 嵌入模型加载失败 | 写入降级为原文存储；索引延后重建 | "记忆可存、检索暂弱"（关键词兜底） | 无 |
| 投影损坏 / 不一致 | 版本标记检出 → 增量或全量重算 | 短暂延迟 | 无（外环可重建） |
| 证据写入失败 | 显式触发类告知未记住；自动类留痕 | 被告知 | 该条丢失（可补救） |
| 存储 / 电量临界 | 停重算与索引重建，保证据写入 | 性能降级 | 无 |
| 时钟异常（回拨） | 单调钟屏蔽；预算与衰减不回退 | 无感 | 无 |
| 密钥丢失 | 按事先定义策略（默认不可恢复） | 档案不可读，家长被告知 | **不可恢复**（R-风险） |
| 内容包验签失败 | 拒绝挂载，保留旧版本 | 无感 | 无 |
| 家长直连被劫持尝试 | 配对验证拒绝，零数据暴露 | 无感 | 无 |

## 8. 关键路径走查

**P1 答题（数据级，离线可用）**：作答 → K1 准入（按元数据版本判诊断性；查归因条件）→ 持久化（事件时间）→ K2 增量重放 → 投影更新 → 策略读新状态。

**P2 对话（智能级）**：发言 → K3 检索（准入过滤 + 审计）→ K4 组装最小上下文 + 禁发校验 → 云端 LLM → 适口性审查 → 儿童端；语义提取入离线队列 → 联网后经 K4 → 结果回 K1 走写入门槛。

**P3 遗忘传播**：确认遗忘（两段证据）→ 沿已确认 `requires` 闭包标记部分掌握 / 达标下游 → 聚合为**一次**诊断小节（先上游后下游）→ 预算内执行 → 证据回 K1。

**P4 元数据版本切换**：K6 验签挂载 → K2 全量重放（旧版本可指定回放）→ 差异聚合为诊断小节 → 变更日志生成家长话术；已发报告不改写。

**P5 删除**：家长验证（C4）→ K5 执行：内核清除 → 外环废弃 → 家长 App 副本失效 → 历史报告去标识 → 审计留痕。

**P6 首日冷启动（v0.1 未覆盖）**：
同意引导（C1）→ 建档案 + 生成密钥 → 可选快速探测（第五锚点"初始画像"）→ 初始估计**一律低置信度** → 首条证据 → 投影建立。
要点：未同意前系统**无记忆**；探测**不得**产出"未掌握"结论（未知 ≠ 未掌握）；首日对话**不得**出现记忆性表述（N-01）；未同意期间主动沟通用非记忆锚点，不退化为纯被动（部署 4.1）。

## 10. 架构禁区

比"应该做什么"更能约束实现的是"不许出现什么"：

1. 除 K1 外**不得**有任何写证据的路径；除 K3 外**不得**有任何读记忆的路径；除 K4 外**不得**有任何外发路径。
2. **不得**在策略层持久化任何状态（压力档位、推荐参数、画像副本）。
3. **不得**跨档案查询（连接粒度 = 单档案）。
4. **不得**在儿童域渲染路径引入成人域内容。
5. **不得**在设备外持久化任何儿童数据（含"临时"缓存）。
6. **不得**散落调用系统时间。
7. **不得**把派生量（重验间隔、下次重验时间、压力档位）作为权威存储。
8. **不得**让推断来源的知识图谱边参与门禁或传播。

## 11. 资源预算（单档案，量级估算）

| 项 | 估算 | 说明 |
| --- | --- | --- |
| 证据量 | 日十条级 → 年 ~4k 条 → 10 年 ~40k 条 | 部署规范 1 的量级 |
| 证据存储 | ~0.5 KB/条 → 10 年 ~20 MB | 加密 SQLite |
| 记忆条目 | 千级 → 数 MB | 含 supersedes 链 |
| 向量索引 | 万级向量 × 384 维 fp16 ≈ 8 MB | kp 千级 + 记忆千级 |
| 嵌入模型 | 20–80 MB（内存峰值 100–200 MB） | **R1 待硬件确认** |
| 全量重放 | 40k 证据 → 百毫秒级 | 纯 CPU 状态机 |
| 向量重建 | 分钟级 + 电量 | 极少发生（模型升级） |
| 检索延迟 | 本地混合检索 ≤ 500 ms 预算 | 记忆 6.4 |

结论：**单档案全量数据在百 MB 量级以内**，本地 SQLite 完全承载；不需要独立向量数据库（呼应 YAGNI）。

## 12. 与 v0.1 的差异清单

独立推导后，两版在设计内核上**收敛**，差异集中在组织方式与覆盖范围：

| 维度 | v0.1 | 本文 | 评价 |
| --- | --- | --- | --- |
| 组织单位 | 组件 + 三咽喉点 | 六份运行时契约 | 本文更贴规范的可否证性；v0.1 更易画图沟通 |
| 存储抽象 | 事件溯源 + 物化投影 | 内核 / 可重建外环 / 可再获取 | 本文显式给出备份与删除顺序规则 |

| 执行模型 | 未展开 | 单写者全序 / 优先级 / 重算窗口 | 本文补齐 |
| 失效分析 | 未展开 | 逐项失效模式表 | 本文补齐 |

| 资源预算 | 未量化 | 百 MB 量级结论 | 本文补齐，支撑 YAGNI 判断 |

**收敛的部分（两版独立得出相同结论，可信度较高）**：单一写入口 / 单一读取口 / 单一外发口；不可变日志 + 可重建投影；每档案物理隔离；本地嵌入；不引入重组件。
