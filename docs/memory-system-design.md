## 1. 设计目标与架构级硬约束

目标：在**设备本地**实现一个满足全部规范的记忆系统，与云端 LLM、家长手机 App、内容下发管道协同工作。

从规范体系中抽取的十条架构级硬约束（设计必须逐条落地）：

| # | 约束 | 出处 |
| --- | --- | --- |
| C1 | `state = f(证据日志, 时间, 元数据版本)`，一切派生量可重放 | 生命周期 2.2 |
| C2 | 三层架构：属性层 / 离散状态层 / 策略层；策略层只读状态 | 生命周期 2.1、压力 10.1 |
| C3 | 本地唯一权威源；出设备仅四类白名单通道 | 部署 2.1 / 2.2 |

## 2. 总体架构

### 2.1 六条设计原则（由约束推导）

1. **三个咽喉点**：一切证据写入经**证据网关**；一切记忆读取经**检索服务**；一切 LLM 调用经**推理网关**。规范里最硬的三条防线（直接证据准入、检索准入过滤、最小必要上下文）收口在三个组件，**禁止**任何旁路路径——新增消费方只能挂接咽喉点，不能自行开库读。
2. **状态即投影**：掌握度等一切派生量是证据日志的确定性投影，物化存储仅为缓存（带版本标记）；任何怀疑即重算。
3. **策略只读**：推荐、压力、沟通选题、探针编排只读投影与记忆，不写状态；它们的输出回流必须再经证据网关成为证据。
4. **物理档案隔离**：每个儿童档案独立加密数据库文件，隔离不依赖查询层 WHERE 子句（AP-LC-08 的纵深防御）。
5. **时间统一注入**：全系统唯一时钟服务，禁止散落的真实时间调用（可测性 #1 的前提）。
6. **一切外发留审计**：四条白名单通道各有专属组件，各自内置审计。

## 4. 关键数据流走查

**流 1 · 答题证据（数据级，离线可用）**
作答 → A1 准入（按当前元数据版本查 binding 与难度→诊断性判定；上游/状态受限→归因标记）→ A2 追加（事件时间）→ A3 增量重放 → A4 投影更新 → B4/B5 读新状态。全程无网络依赖。

**流 2 · 对话（智能级）**
儿童发言 → B1 检索（准入过滤+审计）→ B2 组装最小上下文 → 禁发清单校验 → 云端 LLM → 回复过适口性审查 → 儿童端；语义提取任务 → B3 队列 → 联网后经 B2 → 提取结果回 A1 走写入门槛。

**流 3 · 遗忘传播**
口诀确认遗忘（A5 两段证据完成）→ 沿已确认 requires 闭包标记部分掌握/达标下游为待重验（原因：上游遗忘）→ B4 聚合为诊断小节（先上游后下游）→ 预算内执行 → 证据回 A1。

**流 4 · 元数据版本切换**
C4 验签挂载新快照 → A3 全量重放（旧版本可指定回放）→ 差异进 B4 诊断小节聚合 → 变更日志生成家长可解释话术；已发报告不改写。

**流 5 · 删除（C4 同意 → B8 执行）**
家长验证 → 删除执行器：证据日志按档案清空、A4 投影废弃、A6/A7 记忆与索引清除、B6 通知 App 副本失效、历史报告去标识 → 审计留痕。

## 5. 存储与部署布局

```
设备本地
├── profiles/<child_id>/          ← 每档案独立（物理隔离）
│   ├── evidence.db      (加密 SQLite, WAL；证据日志+审计)
│   ├── memory.db        (加密 SQLite；记忆库+supersedes 链)
│   ├── projection.db    (物化投影，可随时废弃重建)
│   └── vectors.idx      (派生索引，删除级联对象)
├── content/versions/<meta_ver>/  ← 只读内容包（验签后挂载）
├── keystore/                     ← 档案密钥（与密文分离）
└── consent.db                    ← 同意状态（C1–C5）
```

四条白名单通道 ↔ 组件：① 内容下行 → C4；② 家长直连 → B6；③ 推理调用 → B2；④ 匿名遥测（C5 关，默认无）→ 独立模块经 C5 审计。

技术选型基线（YAGNI，C10 量级）：SQLite（WAL）承载全部结构化存储；向量检索用 SQLite 向量扩展或轻量本地索引库；嵌入模型为移动级量化模型（**R1 待硬件确认**）；不引入服务端组件、消息队列（用进程内任务队列替代）。

## 6. 重放架构细节

- **投影版本标记**：每份物化投影记录 `(meta_version, last_evidence_seq, clock_anchor)`；读取方先比对当前三元组，不一致即触发重算（增量：按证据序号续放；全量：从头）。
- **确定性要求**：重放只依赖（证据、时间、元数据版本）三元组；排序不稳定的一切输入（并发序、真实墙钟）在入口处消解——证据按 (事件时间, evidence_id) 全序化。
- **元数据版本切换**：全量重算是重操作（千级 kp × 全证据）；安排在充电/闲置窗口批量执行，期间旧投影继续服务（版本标记保障不一致可检测）；重算结果差异按规范聚合成诊断小节，不逐题打扰。
- **X-01 自比对**：物化投影 vs 重放结果的一致性断言常态化（CI 每日随机剧本）。

## 7. 设计决策与理由

| # | 决策 | 理由 | 被否决的替代 |
| --- | --- | --- | --- |
| D1 | 三咽喉点收口（A1/B1/B2） | 最硬的三条防线集中在三处评审，而非散布全库 | 各组件自行读写（防线被遗忘的风险随消费方数量线性增长） |
| D2 | 事件溯源 + 物化投影 | C1 可重放是第一不变量；导出/导入/元数据重算/污染回滚全部复用同一机制 | 直接可变状态存储（v1 状态机的死因重演） |
| D3 | 策略引擎只读、输出回流走证据网关 | C2 分层；策略污染状态即"推断落盘"变体 | 策略直接写状态（压力档位入状态层，违反压力 10.1） |
| D4 | 每档案独立加密库文件 | 物理隔离是 AP-LC-08 的纵深防御；查询层隔离单点失效即串档 | 单库+child_id 字段隔离（一条漏写 WHERE 即事故） |
| D5 | 本地嵌入模型 | C5：否则每次写入记忆都外发原文，白名单形同虚设 | 云端嵌入 API |
| D6 | SQLite 全承载 | C10 量级下单设备足够；运维零成本；导出即文件 | 引入独立向量数据库/服务中间件（违反 YAGNI） |
| D7 | 探针编排独立于推荐策略 | 探针是"要孩子作答"的总阀门（预算/aging/聚合），多来源共用一个阀门才能防饿死 | 各来源各自排题（预算失控，v3.3 前的缺口重演） |
| D8 | 单一时钟服务+注入点 | 回拨攻击（N-05）与测试时间旅行（M-04 等）都要求时钟收口 | 各处调用系统时间（无法测试、无法防篡改） |
