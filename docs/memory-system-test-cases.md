## 1. 目的与范围

本用例集把六份规范中的行为约束转化为可执行的业务验收，作为记忆系统设计的验收基准与 CI 用例来源。

**范围限定词（元规则的前提）**：本集覆盖——

1. 记忆系统本体（写入 / 检索 / 生命周期 / 隔离安全）；
2. 掌握度记忆生命周期（状态机 + 守卫 + 传播 + 策略约束）;
3. 记忆与主动沟通、双端呈现的**交点**；
4. 数据边界（本地部署、导出 / 导入、家长同意）；
5. 压力与难度调节（与记忆、呈现的**交点**——压力档位本身属策略层，由该子系统用例集全覆盖）。

纯推荐层（AP-LC-20 / 21 / 23 / 24 的非交点部分）与纯交互层（AP-LC-16 / 18 / 19 的非交点部分）由各自子系统的用例集覆盖，本集只测其与记忆的交点。

用例语言为**行为语言**（孩子/家长视角），不含表名字段。

## 2. 方法论

**用例三来源：**

| 来源 | 用例形态 |
| --- | --- |
| 每条"必须"条款 | ≥ 1 个正向用例 |
| 每个高危反模式 | ≥ 1 个反向用例（断言"必须不发生"） |
| 每条不变量 | 1 个属性测试（随机输入断言恒成立） |

**两条原则：**

1. **否决链 = 回归用例清单**：设计否决链（《生命周期规范》附录）每条死因必须映射到一个回归用例（见第 7 章），新增否决结论时同步新增用例；
2. **边界值配对**：守卫类用例（升级 / 降级 / Strike / 阈值）每条配 2–3 个边界变体（恰好达标、差一题、滞回带中间）。

**编写规范：禁止参数固化。** TTL、间隔、预算、阈值等一律由 fixture 提供（见第 5 章参数配置集），断言使用语义表述（"超过当前派生间隔"），不写死业务常数（"90 天"）——否则测试会反逼实现硬编码，污染设计。

**升降级确认的有理由不对称（设计备注）**：失败侧（降级/遗忘）需要**主动确认探针**（两段证据），成功侧（升级）靠**跨时间窗的有机证据**确认，不排针。这不是遗漏——失败需要立刻核实，成功可以等时间证明。防止后人做"对称性修正"。
